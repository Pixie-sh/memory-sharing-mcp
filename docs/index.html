Every agent CLI remembers. None of them remember the same thing.

memory-sharing-mcp gives Claude Code, Pi, OpenCode, Codex and any other MCP client one shared memory store, behind one authenticated service. What you teach one agent, the next one already knows.

The problem

A team on four harnesses keeps four separate memories.

Nobody on a team uses a single agent any more. One person plans in Claude Code, reviews in Codex and runs long jobs in Pi. Each harness keeps its own notes, in its own format, in its own directory.

Every agent calls the same five tools. Only the gateway opens the database.

You repeat yourself

Preferences, decisions and project gotchas get taught once per tool, and drift apart as each copy ages.

Context stops at the tool boundary

A decision confirmed in one CLI is invisible to the agent you open next, so it re-asks or guesses.

Sharing the file directly is unsafe

Pointing several agents at the same database gives you concurrent writers, mismatched runtimes and no record of who wrote what.

How it works

One process owns the store. Agents only talk to it.

Agents connect over Streamable HTTP MCP or through a small stdio adapter, mcp serve. Scripts use the REST API. The gateway validates, authorizes and queues every call before it reaches the store.

One owner

http serve takes an exclusive lock on the store. A second owner refuses to start.

One call at a time

Operations reach the provider strictly in order. Recall updates the store too, so even reads are serialized.

No replayed writes

If a write's outcome is unknown, the call is reported as indeterminate and never retried automatically.

Every write has an author

Each agent can have its own API key. New memories record the key that wrote them as agent_id.

Roles per key

Read-only, read-write and maintenance. Delete and consolidation stay off until you enable them.

Swappable store

Stores plug in as providers. Mnemosyne works today; results follow mem0's memory format whichever store is behind it.
